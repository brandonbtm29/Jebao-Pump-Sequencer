# Jebao Pump Sequencer

PyQt6 app that drives Jebao MD-4.4 / Doser 2.4 4-channel dosing pumps (5 pumps, e.g. "JP 1: EtOH" … "JP 5: Sample") for SPE sequences: manual doses, per-channel calibration, multi-step sequences, and a global emergency stop. Part of Brandon's UAkron lab workspace (shared conventions in `../CLAUDE.md` when the repos are cloned side by side in `GitHub Projects/UAkron/`). GitHub: `brandonbtm29/Jebao-Pump-Sequencer`.

## Run, test, release
- `python jebao_gui.py` (PyQt6 + qasync + requests; Python 3.11+ because the sequence engine uses `Task.cancelling()`). Install with `pip install -e ".[dev]"`; `pyproject.toml` is the only manifest.
- Checks (same as CI, `.github/workflows/ci.yml`): `ruff check .`, `ruff format --check .`, `pytest`. Tests in `tests/` run Qt offscreen, point the data and settings folders at a temp dir before importing `jebao_gui`, and block the network.
- `settings_location.py` is excluded from ruff on purpose: keep it byte-identical to the other UAkron repos.
- Also shared and byte-identical across the UAkron repos (never edit here): `crash_log.py`, `single_instance.py` (one copy at a time; `main()` calls `acquire(APP_NAME)`, `restart_app()` calls `release()` right before `Popen`) and `diagnostics.py` (Settings → App → Copy Diagnostics; `diagnostics_text()` adds `scrub_private()` on top, so pump IDs, MACs and the login never appear).
- Version lives only in `jebao_gui.py` (`__version__`). Releases follow `UAkron Playground/repo-modernization-playbook.md` (Phase 6): bump version, date the CHANGELOG section, annotated tag `vX.Y.Z`, `gh release create --verify-tag`.
- Commits: one concern each, end with a `Co-Authored-By:` trailer for the assistant that did the work. Commit email is the GitHub noreply address.

## Architecture
- **Cloud, not local.** The pumps disable local TCP control once they're on Wi-Fi, so the app uses the Gizwits Open API: log in, list bound devices, then send JSON control POSTs to `https://usapi.gizwits.com/app/control/{did}` (e.g. `{"channe3": true}`; the "channe" spelling is the API's own).
- Emergency stop sends all four channels `false` to every pump.
- `ConfigManager` → `jebao_config.json`: names, calibration (flow rates) and last volumes, keyed by cloud device id (`did`).
- `SecretsManager` → `secrets.json`: Jebao account email and password, and the Discord webhook URL (`discord_webhook`). **Gitignored. Never print, log, commit or copy its contents.**
- Main classes in `jebao_gui.py` (~2,500 lines): `GUILogHandler`/`_LogBridge` (thread-safe log box), `HeadRun`, `AppBox` (Settings → updates + desktop shortcut), `SettingsDialog`, `JebaoPumpGUI`.
- **Sequences (2.7):**
  - **Model:** `sequence.py` (no Qt). A step is `{"kind": dose|staccato|wait|review|sync|sequence, "heads": [[did, ch]], "lanes", "by": volume|time, "volume", "seconds", "burst", "gap", "background", "label", "name", "sound", "message", "cols"}` (`message`: Wait for me only, at most `MAX_MESSAGE` characters; `cols`: see Lanes). `normalize()` reads 2.6 steps (`action`/`pump_did`/`channel`/`val1-3`) and clamps odd values. `to_saved()` also writes the 2.6 fields; a step 2.6 can't run exactly (several pumps, or a dose by time) is saved for it as "Pause (User Review)". Unknown old actions become a 0 s wait.
  - **Lanes (2.9):** a lane is a CH number: `rack.channel_number` = 4 × the pump's stack index + its own channel, so CH1–4 in Stack A and CH5–8 in Stack B. Pumps not in the rack get CH1–4. `heads` always hold the pump's own channel 1–4, which is what commands use.
    - **Pumping steps:** a pumping step's lanes are its heads' CH numbers (`ctx.lane_of`), and each lane runs only its own heads (`heads_in_lane`).
    - **Other kinds:** they use `cols` (CH numbers). Steps from 2.8 and older have no `cols`: their `lanes` are pump channels and expand to that channel on each stack the sequence pumps on (`pumping_lanes`/`for_steps` → `Context.expand`). That's what they did when CH1 and CH5 were one lane. `to_saved` writes `lanes` from `cols` mod 4 for older copies.
    - **Host:** `channel_number(did, ch)` (cached on the rack + pump list), `all_lanes()` and `_lane_for(key)`, fixed per run in `_run_lane_of`.
    - **Per-lane state:** `_ch_paused`, `_ch_review_events` and similar are dicts by CH number. The banner grows Continue buttons as needed (`_approve_buttons`).
    - Sub-sequences are flattened (`flatten`, recursion guard).
  - **Checks (2.11):** each sequence has its own `checks_settings()` dict (`same_channel`, `offline`, `calibration`: off/warn/stop, and `calibration_days`). Saved ones are in `config['saved_sequence_checks'][name]` (not in the step list, so older versions still read `saved_sequences`), the draft's in `config['sequence_checks']`. `ChecksDialog` edits them; they go into undo snapshots, save/rename/duplicate/delete, export/import, `plan_sequence(checks=)` and `enqueue(checks=)` → the queue item → `_async_run_sequence(checks=)` → `self._run_checks`. `plan()` records each head's pumping spans per lane and `same_channel_overlaps()` finds two heads in one lane at once; "stop" makes it an error.
  - **Plans:** `plan()` simulates the lanes with `pumpguard.OnTimeBudget` and the guard's `resting_need()`, giving times, rests, per-head volumes, liquids, reviews and the "Before you run" checks. `step_problem()` decides when a pumping step can't run; such a step fails the run. Plans are bounded: `MAX_BURSTS` 5000, `SIM_LIMIT` 8000 limit-aware pumping runs, old budget spans pruned. They run on the event loop that drives the pumps, so keep them fast.
  - **Run state:** `RunState`/`LaneState` hold the step × lane cells and each lane's status, detail and mL. `SyncPoint` lets a skipped lane count as arrived. The run history is `<data>/logs/runs-<computer>.jsonl`.
  - **Engine (`jebao_gui.py`):**
    - `_queue_worker` (only one at a time) → `_queue_step` → `_run_queued`; it waits while `queue_paused` unless `_run_one` (Run now).
    - `_async_run_sequence` creates one `_run_lane` task per lane. Each step runs as its own task in `_ch_step_tasks`, so `skip_step(ch)` cancels just that step: `_skip[ch] == path` and the lane's `cancelling()` is 0.
    - Background steps go in `_ch_running_tasks`. If one fails, `_background_done` → `_fail_run`.
    - `_run_head` uses `_timed_run`, with a `meter` for mL delivered, and waits while its head is busy. `_together` cancels sibling heads if one fails.
    - Pause per lane is `pause_lane` (`_ch_paused`, polled). `stop_run()` pauses the queue and sets `run.stopping`; Stop and Skip are ignored after that.
    - The `finally` keeps waiting up to 15 s for every task's OFF, even if cancelled again. It then releases reviews, records history and calls `sequencer_tab.run_finished`.
    - A failed or stopped run pauses the queue.
    - **Wait for me message:** `_ch_review_messages[ch]` and `_review_at[ch]` (the step's path) are set while a lane waits. The message goes in the orange bar and the lane's detail, and the taskbar button flashes (`QApplication.alert`). There is no pop-up since 2.11 (it was a `ReviewPopup`); never open a modal dialog from the engine, because a nested event loop would stall the pumps.
  - **UI:** `sequencer_tab.py` = `SequencerTab(host)` with Build / Preview / Running pages. `splitter` is `host.seq_splitter` (the sidebar divider, 2 panes, remembered per computer).
    - **Build:** library sidebar and queue; `StepList` + `StepDelegate` cards with InternalMove drag (`reordered`); the inspector is rebuilt on selection. The draft lives in `config['sequence']`, `['sequence_name']` and `['sequence_source']`, with undo snapshots.
    - **Preview:** `Timeline` (QPainter) and the per-head table.
    - **Running:** `LaneCard` per lane and a progress grid. It refreshes from `host.ui_timer`.
- **2.0 layout:** top bar (status, Refresh, Settings) → approval banner → tabs **Manual | Sequencer | Calibration | Rack** in a vertical splitter with the System Log → Emergency Stop → status bar (clock, version). `rack_widgets.py` holds `ManualTab` (PumpCard + `HeadTile`, selection, Dispense panel, S/M/L sizes in `config['ui']`) and `RackTab` (TrayList + `SlotWidget` drag-and-drop with MIME `application/x-jebao-pump`, click-to-place fallback, pump/head names). Both use the main window as `host` (see the module docstring for the methods). `HeadGrid` (the rack of selectable tiles, optional `status_for(did, ch)` hook for the status line) is shared by the Manual and Calibration tabs; tile size is shared via `host.tile_size_changed`. `refresh_pumps()` re-sorts `cloud_devices` in rack order and rebuilds the tabs; `ui_timer` (300 ms) refreshes only the tab in view (plus `calibration_tab._watch_cancel()`).
- **Rack tab rebuilds later (2.8):** a change in the Rack tab saves at once (`_apply` writes `config['rack']`, `_save_names` writes names) and rebuilds the tabs with `QTimer.singleShot(0)` (`_later`). Never rebuild or delete widgets from inside one of their own signals (editingFinished from a click elsewhere, a button's clicked, a drop): Qt then delivers the rest of that event to a deleted widget, a native crash (access violation on Windows, no Python traceback, only `jebao_pump_sequencer.fatal.log`). `_names_for` is the pump whose names are in the boxes; `slot_clicked`/`_tray_clicked` save them before switching. The Sequencer tab does the same for library clicks and card drops.
- **Jebao app names (2.8):** `cloud_name(did)` is the pump's `dev_alias` from `/app/bindings`; `cloud_note(did)` ("Jebao app: …") is shown when the app's own name differs (Rack slots and tray, Manual pump cards, Names panel with `product_name` and MAC, connection report, head picker tooltips).
- `rack.py`: layout data in `config['rack']` (`name`, `slots_per_stack`, `stacks[{name, slots[did|None]}]`), pure functions (place = swap, remove, resize, auto_arrange, natural_key). First 2.0 run: `rack_layout()` builds one stack from the old `pump_order`. Names: `config['pumps'][did]['display_name']`, `['head_names']` (4), `['calibrated_at']` (4 ISO dates; 1.0 mL/min with no date = "not calibrated").
- **Calibration (2.1):** `calibration_tab.py` = `CalibrationTab` (HeadGrid with `scroll=False` and its `toolbar` pinned above one scroll area holding the grid, the live `MassChart` and the results table; Automatic/Manual pages on the right). `autocal.py` (no Qt) = `Settings`, `fit_line`, `evaluate`, `AutoCalibrator` (async; one head at a time: settle until still → ON until ~volume by balance or `max_run_s` → OFF → settle until still; two-pass fit with the ignore margins counted from the detected flow start/stop; saves the **slope** rate; pass = R² and first-half vs second-half slope within `tolerance_pct`; start/stop delays = where the line meets start/end mass, reported not judged; Δmass rate kept for the record; retries only R²/steadiness misses; no-flow fails that head; a pump or balance failure stops the run; injectable `clock`/`sleep`), `write_csv`. `balance.py` (no Qt) = MT-SICS `SI` polling and streamed-line parsers (grams), `SerialBalance` reader thread with a sample deque, `SimulatedBalance` for tests. Host hooks: `set_head`, `save_head_rate` (sets rate + `calibrated_at`), `data_dir` (CSV in `<data>/calibrations/`), `calibration_running()` (queued sequences wait). Settings in `config['autocal']`. Tubing ID/OD are no longer edited (old values kept).
- System log: **Hide/Show** (`set_log_collapsed`, saved as `config['ui']['log_collapsed']`) hides the text box, caps the group's height and shows the latest line in `lbl_log_info`.
- **Pump guard (2.5):** `pumpguard.py` (no Qt). `send_cloud_command()` → `guard.command()` → `_post_control()` (raw HTTP).
  - **Bookkeeping:** the guard records `app_on`/`last_cmd`, takes one `asyncio.Lock` per head so commands never overlap, and tracks commands still in flight.
  - **Failed commands:** a failed OFF, or a failed or cancelled ON, goes into `must_off`. `_keep_stopping` retries with back-off; after a failed ON it sends a second OFF 12 s later (also when another path's OFF got there first).
  - **Cancelled commands (2.7):** `command()` sends through a shielded task. If the caller is cancelled, `_finish` waits up to `FINISH_WAIT_S` for the request, so a later OFF can't overtake a late ON; a cancelled ON is then stopped. An OFF cancelled before it went out is put in `must_off`. `only_if` is checked once the lock is held (the guard's re-ON uses it).
  - **Confirming OFF:** an OFF to a head that was on stays in `unconfirmed` until the pump's report (`_read_pump`: GET `/app/devdata/{did}/latest` → `attr.channe1..8`, `updated_at`) shows it at 0. This applies only when reports can be read, or when the pump is offline.
  - **`check()` after every pump-list fetch:** stops orphans (app_on but no HeadRun after 20 s), stops non-resting runs that are over the limit, and stops heads that report ON while the app has them off. It also re-sends ON once if a dose's head reports OFF.
  - **On-time budget:** `OnTimeBudget`. `head_limit()` comes from `config['guard']` (enabled, on_min, window_min) or a per-head `config['pumps'][did]['limits'][ch-1]` (None/"off"/minutes).
  - **Resting:** `_interruptible_motor_run` calls `_rest_head` when `guard.over_limit`, and the tile shows "Resting".
  - **ON failures:** `_turn_on` retries 3 times, then raises, so the step fails loudly. `_timed_run` sends OFF in `finally`.
  - **One head per channel (2.11):** `_turn_on(did, ch, source)` first calls `_check_channel`, which raises `ChannelBusy` (a RuntimeError, so the step or manual head fails with that reason) if `_channel_user()` finds another head with the same CH number that is on (guard `app_on`, ON in flight, `must_off`, OFF unconfirmed while offline, a running `HeadRun`) or whose ON is on its way (`_claims`, taken synchronously before the ON so two heads starting together can't both pass). `_channel_rule(source)`: a sequence follows `_run_checks['same_channel']` ("warn" only logs), the Manual tab `config['guard']['one_per_channel']` (default on), calibration isn't checked. `dispense()` claims its heads before its tasks start and releases them once the ON went out (or the task ended). `channel_problems(heads)` feeds the Manual tab's warning before anything starts.
  - **Emergency Stop:** `guard.hold(15)` refuses ON, and Async steps and manual dose tasks are cancelled.
  - **Close and banner:** `pending()` feeds the red `guard_bar` (with an "I've switched it off" button), `busy_reason` and `_stop_then_close`, which asks "Close anyway?".
- **Discord notifications (2.10):** `discord_notify.py` (no Qt) = `check_url` (Discord webhook URLs only), `scrub` (blanks webhook URLs from text), `settings()` (`config['discord']` with defaults: `enabled`, `events`, `pings`, `mention_id`, `mention_kind`), `Note`, `payload()` (escapes Markdown; `allowed_mentions` only ever lists the one ID set, so no @everyone), `Notifier` (one daemon thread, a queue; notes with the same `group` within `GROUP_WAIT_S` merge; retries 429/5xx/connection errors, gives up on other 4xx; logs failures without the URL). `discord_dialog.py` = `DiscordDialog` (Settings → Discord; URL saved in secrets, the rest in config).
  - **App side:** `notify(event, title, body, fields, items, group, ping)` checks the settings and passes `_discord_text` (pump IDs and MACs → "a pump"). Hooks: `_notify_review` (in `_run_step`), `_notify_outcome` (the run's `finally`), `_notify_guard` (from `refresh_guard_banner`, also every 5 s by `guard_timer`; heads pending ≥ `GUARD_NOTIFY_S`, then an all-clear), `_notify_online` (from `_note_online_changes`, only for pumps in use), and a rest note in `_rest_head`. `closeEvent` gives the thread 2 s to send what's left. The webhook URL and its token are in `private_values()`.
  - **Lab Manager bot (2.12):** `config['discord']['mode'] == "bot"` (then `notify()` sends nothing; the webhook stays for people without a bot). Token in `secrets['discord_bot_token']` (in `private_values()`); `channel_id`, `allowed_ids` (default: the pinged user), `keep_days`.
    - `lab_manager.py` (no Qt) = `LabManager` (discord.py, imported only when started, in its own thread and event loop; `Intents.none()`, presses arrive as `on_interaction`), `Reconciler` (makes the channel match `{key: Spec}`: post/edit/delete; progress-only edits at most every `EDIT_EVERY_S`, anything with a new `sig` at once; `final` cards are kept and deleted after `keep_days`; ids saved in `<data>/logs/lab-manager-<computer>.json`, leftovers from a crashed session tidied on connect, carried over when the bot restarts in the same session), `decide()` (buttons are `lm:<instance>:<action>:<arg>`; another instance's are ignored, so two computers can share the bot; people not in `allowed` are refused). Stop asks to confirm in an ephemeral message (`stopyes`).
    - `lab_cards.py` = `specs(host, settings, instance)`: the run card (`card:<_run_id>`), a ping per Wait for me step lanes wait at (`wait:<run>:<path>`; Continue buttons only if the step's `remote` is set), and alerts (`alert:guard`, `alert:offline`, `alert:<run>` for a failed run until "Got it").
    - **App side:** `restart_lab()` (from `start_background_tasks` and the dialog's OK), `_publish_lab()` every 3 s (`lab_timer`) and after each hook, `_lab_action_from_bot` → `_LabBridge.pressed` (Qt signal, main thread) → `lab_do(action, arg, user)`, which re-checks the run id, the step path, that the lane still waits and that the step allows it, logs `[Discord] <name> …`, and answers through a concurrent Future. `closeEvent` publishes once more and stops the bot (up to 3 s).
- **Pump Wi-Fi watch (2.4):** after the first successful `fetch_devices()`, `_watch_pumps()` re-fetches `/app/bindings` every `netwatch.POLL_S` (30 s) with `quiet=True` (same pumps → update `is_online` in place, no tab rebuild; changed list → `refresh_pumps()`; token error 400/401/403 → `login_and_fetch()` once). `netwatch.py` (no Qt) = `ConnectionLog`: online/offline transitions → events saved to `<data>/logs/connection-<computer>.jsonl` (pruned with `log_keep_days`), cloud check times, per-pump summary. `network_report.py` = `NetworkDialog` (status-bar `pumps_button` or Settings → Pump Connections). The pumps' Wi-Fi itself can't be seen through the cloud; this only records when they drop.
- `closeEvent` asks before quitting while `busy_reason()` is set, then sends Emergency Stop and closes.
- **Head runs:** `head_runs[(did, ch)] = HeadRun` while a motor is on. `_interruptible_motor_run(ch, did, s, source, lane=)` registers one for sequences (`ch` is the pump's own channel; the lane's `_ch_paused/_ch_cancelled` apply, and `HeadRun.lane` records it) and manual doses; automatic calibration registers its head (`source="calibration"`; cancelling it stops the calibration). `dispense(heads, value, unit)` groups heads per pump (one ON per pump), skips offline/running/zero-rate heads; `pause_heads/resume_heads/cancel_heads` act per head; Emergency Stop cancels all. Cancelling a head inside a running sequence stops that sequence.
- `updater.py`: checks GitHub's latest release, fast-forwards a git clone to the tag, reinstalls (`pip install -e .`) only if `pyproject.toml` changed, rolls back on failure. Same design as Balance-Streamer-GUI and Masterflex. `JebaoPumpGUI.busy_reason()` blocks updating while a sequence/queue, manual dose or calibration is running (`_motor_jobs` counter).
- Startup (`main()` → `start_background_tasks()` after 1.5 s): one GitHub release check unless `config['check_updates_on_start']` is False (Settings → App checkbox; bottom-right `version_button` turns orange when outdated, no dialog; click → Settings update offer) and `maintain_desktop_shortcut()` (creates the shortcut on first launch, refreshes it when `__version__` changed; per-copy record `desktop_shortcut.json`, gitignored; off via the Settings checkbox). Neither runs in tests (they never call `main()`).
- `eventlog.py`: the system log on disk. `main()` prunes and loads this computer's history (`JebaoPumpGUI(history=...)`) and adds `DailyFileHandler` → `<data>/logs/events-YYYY-MM-DD-<computer>.log` (same folder as crash_log.py's error log) (computer name in the file name so SyncThing never sees two writers). Retention `log_keep_days` in jebao_config (default 30, Settings). Tests never call `main()`, so they don't write logs.
- Since 1.4.0: approvals are an orange banner (`refresh_approval_banner()`, "Continue CHn" buttons only for waiting channels; since 2.7 it names the step from `_ch_review_titles`); clock in the status bar; Restart only in Settings → App.
- `shortcut.py`: desktop shortcut per OS (Windows .lnk via PowerShell with env-var values, macOS .app bundle, Linux .desktop), pointing at this clone's Python and `jebao_gui.py`. Icons in `assets/` (drawn by `scripts/make_icon.py`).

## Where code and data live
- **Code** (this repo) is cloned outside SyncThing: `%USERPROFILE%\GitHub Projects\UAkron\Jebao-Pump-Sequencer` on Windows, `~/GitHub Projects/UAkron/Jebao-Pump-Sequencer` on the Mac. It syncs through GitHub only.
- **Instrument data** stays in SyncThing: `%USERPROFILE%\SyncThing\UAkron Playground\Jebao Pump\` (Mac: `~/SyncThing/UAkron Playground/Jebao Pump/`). Never copy data into the repo, and never commit the settings files listed below.
- **How it works:** at startup the app `chdir`s into its SyncThing data folder (`DATA_DIR`, override with `UAKRON_APP_DATA_DIR` or `UAKRON_DATA_DIR`). Every relative data path (`Data/`, `Data Backups/`, `Sessions/`, run logs) therefore resolves inside SyncThing, and the default save folder is `Data` there. Files that ship with the code (icons, the OCR model) must be loaded via `script_dir` / `__file__`, never by bare relative name. Run the app from this clone.
- **Settings folder (since 10 Oct 2026):** the settings files (`jebao_config.json`, `secrets.json`) are read from `CONFIG_DIR`, resolved by `settings_location.py` (identical copy in every UAkron repo). Default: this repo folder (gitignored), so a fresh clone starts from the app's defaults. The per-machine pointer `settings_location.json` (gitignored), set from the app's "Settings Folder" box, can move them; a relative path is relative to the data folder. Brandon's machines point at `Settings`, i.e. `UAkron Playground/<App>/Settings/` in SyncThing, so settings stay identical across computers (including `secrets.json`; never print it). `UAKRON_SETTINGS_DIR` overrides the pointer. Store save folders relative to the data folder (e.g. `Data`), not as absolute paths.

## Launch
Double-click `Launch_Windows.bat` / `Launch_Mac.command`. If this repo's `.venv` is missing they first create it and run `pip install -e .` (same commands and Python 3.11+ checks as `Setup_*`, which are now only for repair/reinstall). They check the packages import, then start the app detached (Windows `pythonw` via `start`; macOS a new session via `subprocess.Popen(start_new_session=True)`) and close their console/Terminal window. For development, `pip install -e ".[dev]"` into the same `.venv`. Window size/position and splitter sizes live in `window_state.json` in the app folder (per computer, gitignored, not in the settings folder). Windows Smart App Control may be on; if a DLL import is "blocked by an Application Control policy", retry once before investigating.
