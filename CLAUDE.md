# Jebao Pump Sequencer

PyQt6 app that drives Jebao MD-4.4 / Doser 2.4 4-channel dosing pumps (5 pumps, e.g. "JP 1: EtOH" … "JP 5: Sample") for SPE sequences: manual doses, per-channel calibration, multi-step sequences, and a global emergency stop. Part of Brandon's UAkron lab workspace (shared conventions in `../CLAUDE.md` when the repos are cloned side by side in `GitHub Projects/UAkron/`). GitHub: `brandonbtm29/Jebao-Pump-Sequencer`.

## Run, test, release
- `python jebao_gui.py` (PyQt6 + qasync + requests; Python 3.11+ because of `asyncio.Barrier`). Install with `pip install -e ".[dev]"`; `pyproject.toml` is the only manifest.
- Checks (same as CI, `.github/workflows/ci.yml`): `ruff check .`, `ruff format --check .`, `pytest`. Tests in `tests/` run Qt offscreen, point the data and settings folders at a temp dir before importing `jebao_gui`, and block the network.
- `settings_location.py` is excluded from ruff on purpose: keep it byte-identical to the other UAkron repos.
- Also shared and byte-identical across the UAkron repos (never edit here): `crash_log.py`, `single_instance.py` (one copy at a time; `main()` calls `acquire(APP_NAME)`, `restart_app()` calls `release()` right before `Popen`) and `diagnostics.py` (Settings → App → Copy Diagnostics; `diagnostics_text()` adds `scrub_private()` on top, so pump IDs, MACs and the login never appear).
- Version lives only in `jebao_gui.py` (`__version__`). Releases follow `UAkron Playground/repo-modernization-playbook.md` (Phase 6): bump version, date the CHANGELOG section, annotated tag `vX.Y.Z`, `gh release create --verify-tag`.
- Commits: one concern each, end with a `Co-Authored-By:` trailer for the assistant that did the work. Commit email is the GitHub noreply address.

## Architecture
- **Cloud, not local.** The pumps disable local TCP control once they're on Wi-Fi, so the app uses the Gizwits Open API: log in, list bound devices, then send JSON control POSTs to `https://usapi.gizwits.com/app/control/{did}` (e.g. `{"channe3": true}`; the "channe" spelling is the API's own).
- Emergency stop sends all four channels `false` to every pump.
- `ConfigManager` → `jebao_config.json`: names, calibration (flow rates) and last volumes, keyed by cloud device id (`did`).
- `SecretsManager` → `secrets.json`: Jebao account email and password. **Gitignored. Never print, log, commit or copy its contents.**
- Main classes in `jebao_gui.py` (~2,500 lines): `GUILogHandler`/`_LogBridge` (thread-safe log box), `HeadRun`, `CheckableComboBox`, `AppBox` (Settings → updates + desktop shortcut), `SettingsDialog`, `JebaoPumpGUI`.
- **2.0 layout:** top bar (status, Refresh, Settings) → approval banner → tabs **Manual | Sequencer | Calibration | Rack** in a vertical splitter with the System Log → Emergency Stop → status bar (clock, version). `rack_widgets.py` holds `ManualTab` (PumpCard + `HeadTile`, selection, Dispense panel, S/M/L sizes in `config['ui']`) and `RackTab` (TrayList + `SlotWidget` drag-and-drop with MIME `application/x-jebao-pump`, click-to-place fallback, pump/head names). Both use the main window as `host` (see the module docstring for the methods). `HeadGrid` (the rack of selectable tiles, optional `status_for(did, ch)` hook for the status line) is shared by the Manual and Calibration tabs; tile size is shared via `host.tile_size_changed`. `refresh_pumps()` re-sorts `cloud_devices` in rack order and rebuilds the tabs; `ui_timer` (300 ms) refreshes only the tab in view (plus `calibration_tab._watch_cancel()`).
- `rack.py`: layout data in `config['rack']` (`name`, `slots_per_stack`, `stacks[{name, slots[did|None]}]`), pure functions (place = swap, remove, resize, auto_arrange, natural_key). First 2.0 run: `rack_layout()` builds one stack from the old `pump_order`. Names: `config['pumps'][did]['display_name']`, `['head_names']` (4), `['calibrated_at']` (4 ISO dates; 1.0 mL/min with no date = "not calibrated").
- **Calibration (2.1):** `calibration_tab.py` = `CalibrationTab` (HeadGrid with `scroll=False` and its `toolbar` pinned above one scroll area holding the grid, the live `MassChart` and the results table; Automatic/Manual pages on the right). `autocal.py` (no Qt) = `Settings`, `fit_line`, `evaluate`, `AutoCalibrator` (async; one head at a time: settle until still → ON until ~volume by balance or `max_run_s` → OFF → settle until still; two-pass fit with the ignore margins counted from the detected flow start/stop; saves the **slope** rate; pass = R² and first-half vs second-half slope within `tolerance_pct`; start/stop delays = where the line meets start/end mass, reported not judged; Δmass rate kept for the record; retries only R²/steadiness misses; no-flow fails that head; a pump or balance failure stops the run; injectable `clock`/`sleep`), `write_csv`. `balance.py` (no Qt) = MT-SICS `SI` polling and streamed-line parsers (grams), `SerialBalance` reader thread with a sample deque, `SimulatedBalance` for tests. Host hooks: `set_head`, `save_head_rate` (sets rate + `calibrated_at`), `data_dir` (CSV in `<data>/calibrations/`), `calibration_running()` (queued sequences wait). Settings in `config['autocal']`. Tubing ID/OD are no longer edited (old values kept).
- System log: **Hide/Show** (`set_log_collapsed`, saved as `config['ui']['log_collapsed']`) hides the text box, caps the group's height and shows the latest line in `lbl_log_info`.
- **Pump guard (2.5):** `pumpguard.py` (no Qt). `send_cloud_command()` → `guard.command()` → `_post_control()` (raw HTTP).
  - **Bookkeeping:** the guard records `app_on`/`last_cmd`, takes one `asyncio.Lock` per head so commands never overlap, and tracks commands still in flight.
  - **Failed commands:** a failed OFF, or a failed or cancelled ON, goes into `must_off`. `_keep_stopping` retries with back-off; after a failed ON it sends a second OFF 12 s later.
  - **Confirming OFF:** an OFF to a head that was on stays in `unconfirmed` until the pump's report (`_read_pump`: GET `/app/devdata/{did}/latest` → `attr.channe1..8`, `updated_at`) shows it at 0. This applies only when reports can be read, or when the pump is offline.
  - **`check()` after every pump-list fetch:** stops orphans (app_on but no HeadRun after 20 s), stops non-resting runs that are over the limit, and stops heads that report ON while the app has them off. It also re-sends ON once if a dose's head reports OFF.
  - **On-time budget:** `OnTimeBudget`. `head_limit()` comes from `config['guard']` (enabled, on_min, window_min) or a per-head `config['pumps'][did]['limits'][ch-1]` (None/"off"/minutes).
  - **Resting:** `_interruptible_motor_run` calls `_rest_head` when `guard.over_limit`, and the tile shows "Resting".
  - **ON failures:** `_turn_on` retries 3 times, then raises, so the step fails loudly. `_timed_run` sends OFF in `finally`.
  - **Emergency Stop:** `guard.hold(15)` refuses ON, and Async steps and manual dose tasks are cancelled.
  - **Close and banner:** `pending()` feeds the red `guard_bar` (with an "I've switched it off" button), `busy_reason` and `_stop_then_close`, which asks "Close anyway?".
- **Pump Wi-Fi watch (2.4):** after the first successful `fetch_devices()`, `_watch_pumps()` re-fetches `/app/bindings` every `netwatch.POLL_S` (30 s) with `quiet=True` (same pumps → update `is_online` in place, no tab rebuild; changed list → `refresh_pumps()`; token error 400/401/403 → `login_and_fetch()` once). `netwatch.py` (no Qt) = `ConnectionLog`: online/offline transitions → events saved to `<data>/logs/connection-<computer>.jsonl` (pruned with `log_keep_days`), cloud check times, per-pump summary. `network_report.py` = `NetworkDialog` (status-bar `pumps_button` or Settings → Pump Connections). The pumps' Wi-Fi itself can't be seen through the cloud; this only records when they drop.
- `closeEvent` asks before quitting while `busy_reason()` is set, then sends Emergency Stop and closes.
- **Head runs:** `head_runs[(did, ch)] = HeadRun` while a motor is on. `_interruptible_motor_run(ch, did, s, source)` registers one for sequences (channel-level `_ch_paused/_ch_cancelled` still apply) and manual doses; automatic calibration registers its head (`source="calibration"`; cancelling it stops the calibration). `dispense(heads, value, unit)` groups heads per pump (one ON per pump), skips offline/running/zero-rate heads; `pause_heads/resume_heads/cancel_heads` act per head; Emergency Stop cancels all. Cancelling a head inside a running sequence stops that sequence.
- `updater.py`: checks GitHub's latest release, fast-forwards a git clone to the tag, reinstalls (`pip install -e .`) only if `pyproject.toml` changed, rolls back on failure. Same design as Balance-Streamer-GUI and Masterflex. `JebaoPumpGUI.busy_reason()` blocks updating while a sequence/queue, manual dose or calibration is running (`_motor_jobs` counter).
- Startup (`main()` → `start_background_tasks()` after 1.5 s): one GitHub release check unless `config['check_updates_on_start']` is False (Settings → App checkbox; bottom-right `version_button` turns orange when outdated, no dialog; click → Settings update offer) and `maintain_desktop_shortcut()` (creates the shortcut on first launch, refreshes it when `__version__` changed; per-copy record `desktop_shortcut.json`, gitignored; off via the Settings checkbox). Neither runs in tests (they never call `main()`).
- `eventlog.py`: the system log on disk. `main()` prunes and loads this computer's history (`JebaoPumpGUI(history=...)`) and adds `DailyFileHandler` → `<data>/logs/events-YYYY-MM-DD-<computer>.log` (same folder as crash_log.py's error log) (computer name in the file name so SyncThing never sees two writers). Retention `log_keep_days` in jebao_config (default 30, Settings). Tests never call `main()`, so they don't write logs.
- Since 1.4.0: approvals are an orange banner (`refresh_approval_banner()`, buttons only for waiting channels); clock in the status bar; Restart only in Settings → App. The Sequencer's blank Pump cell on Pause/Wait/Sub-sequence rows is intentional (those steps act on a channel, not a pump).
- `shortcut.py`: desktop shortcut per OS (Windows .lnk via PowerShell with env-var values, macOS .app bundle, Linux .desktop), pointing at this clone's Python and `jebao_gui.py`. Icons in `assets/` (drawn by `scripts/make_icon.py`).

## Where code and data live
- **Code** (this repo) is cloned outside SyncThing: `%USERPROFILE%\GitHub Projects\UAkron\Jebao-Pump-Sequencer` on Windows, `~/GitHub Projects/UAkron/Jebao-Pump-Sequencer` on the Mac. It syncs through GitHub only.
- **Instrument data** stays in SyncThing: `%USERPROFILE%\SyncThing\UAkron Playground\Jebao Pump\` (Mac: `~/SyncThing/UAkron Playground/Jebao Pump/`). Never copy data into the repo, and never commit the settings files listed below.
- **How it works:** at startup the app `chdir`s into its SyncThing data folder (`DATA_DIR`, override with `UAKRON_APP_DATA_DIR` or `UAKRON_DATA_DIR`). Every relative data path (`Data/`, `Data Backups/`, `Sessions/`, run logs) therefore resolves inside SyncThing, and the default save folder is `Data` there. Files that ship with the code (icons, the OCR model) must be loaded via `script_dir` / `__file__`, never by bare relative name. Run the app from this clone.
- **Settings folder (since 10 Oct 2026):** the settings files (`jebao_config.json`, `secrets.json`) are read from `CONFIG_DIR`, resolved by `settings_location.py` (identical copy in every UAkron repo). Default: this repo folder (gitignored), so a fresh clone starts from the app's defaults. The per-machine pointer `settings_location.json` (gitignored), set from the app's "Settings Folder" box, can move them; a relative path is relative to the data folder. Brandon's machines point at `Settings`, i.e. `UAkron Playground/<App>/Settings/` in SyncThing, so settings stay identical across computers (including `secrets.json`; never print it). `UAKRON_SETTINGS_DIR` overrides the pointer. Store save folders relative to the data folder (e.g. `Data`), not as absolute paths.

## Launch
Double-click `Launch_Windows.bat` / `Launch_Mac.command`. If this repo's `.venv` is missing they first create it and run `pip install -e .` (same commands and Python 3.11+ checks as `Setup_*`, which are now only for repair/reinstall). They check the packages import, then start the app detached (Windows `pythonw` via `start`; macOS a new session via `subprocess.Popen(start_new_session=True)`) and close their console/Terminal window. For development, `pip install -e ".[dev]"` into the same `.venv`. Window size/position and splitter sizes live in `window_state.json` in the app folder (per computer, gitignored, not in the settings folder). Windows Smart App Control may be on; if a DLL import is "blocked by an Application Control policy", retry once before investigating.
